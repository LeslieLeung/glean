# 订阅管理

Manage Feeds 位于设置页；独立订阅页面和阅读器侧栏继续保留，并共用添加、编辑和 OPML 导入结果弹窗。

## 文件夹与编辑

- 桌面端显示目录树；窄屏使用带完整路径的目录选择器。
- 全部订阅、未分类和具体目录分别筛选。选择父目录时包含其后代目录，搜索和分页在当前范围内进行。
- 编辑仅支持自定义标题和文件夹；标题清空恢复订阅源标题。只移动目录不会清空标题。
- URL 只读，接口拒绝修改 URL。更换地址必须取消原订阅后重新添加。

## 添加订阅

输入 RSS / Atom 或网站地址后先验证。预览展示解析到的标题和最终订阅地址，确认后再创建订阅。修改输入地址后必须重新验证。

后端在创建时重新校验，失败不创建 Feed 或 Subscription。已有订阅提示其目录，合法但没有文章的源可以添加。HTTP 重定向后的 URL 用于订阅身份与网站内相对链接解析。

## 拉取健康和刷新

- `last_fetched_at` 是最近尝试时间；`last_success_at` 是最近成功时间。
- 最近失败展示警告与可展开的原因、连续失败次数。达到停抓条件时明确提示停止自动拉取，允许手动重试。
- HTTP 304 属于成功，清除旧错误并更新成功时间和下一次拉取时间。
- 手动、首次、OPML 和定时拉取共享同一个 Feed job ID。排队及执行期间不重复创建任务，结果保留 5 秒作为刷新冷却。
- 前端显示排队、刷新、完成结果；正在进行的任务通过服务端状态恢复。任务状态查询失败或任务过期不等同于订阅源失效。
- 拉取失败先回滚部分文章与元数据，再持久化错误。自动重试由定时扫描配合 `next_fetch_at` 的退避规则执行。

## OPML

导入和导出保留最多 5 层文件夹、空目录，以及不同父目录下的同名文件夹。目录名称中的 `/` 不作为层级分隔符。

导入先校验订阅内容，再逐项创建；有效项继续处理，无效和重复项保留在失败清单中，包含标题、原 URL、完整目录与原因。已有目录按完整路径复用，导入标题作为用户自己的自定义标题保存。导入期间保持进行中状态，不显示伪造的百分比。

## 升级

本次新增数据库迁移 `f2b67e19a830`，为 Feed 添加可空的 `last_success_at`。历史尝试时间无法证明成功，因此不回填。

部署时先执行 `make db-upgrade`，再重启 API 和 worker，使所有拉取入口采用统一任务标识。前端使用同一次更新的 API 类型。

本地 Node 版本启用实验性 Web Storage 时，Vitest 可使用 `NODE_OPTIONS=--no-experimental-webstorage`，让测试使用 jsdom 的 localStorage。
